# 光学研究环境开发

[English](DEVELOPMENT.md) · [贡献说明](../CONTRIBUTING.md) · [源码导航](../AGENTS.md)

本环境负责接入科学软件、运行完整研究程序并保存可解释的结果。它独立安装和运行，可供不同 Agent、研究系统和仪器控制程序使用。具体版本的变化记录在 [RELEASE.md](RELEASE.md)。

## 职责

| 层次 | 负责什么 | 扩展位置 |
| --- | --- | --- |
| 科学程序 | 物理模型、数值方法、观测量和解释 | Python 或原生语言程序，声明输入和结果 |
| 软件接入 | 求解器身份、安装与连接、程序和指南 | 独立安装的静态接入包、本地登记 |
| 执行 | 依赖、尝试次数、资源分配和接续 | `jobs`、`worker`、`execution`、`progress` |
| 科学数据 | 数组、单位、坐标和物理约定 | `data`、`arrays`、文件绑定 |
| 宿主接口 | 发现、提交、取消和按需读取 | Python、CLI、MCP、TypeScript |
| 原生进程 | 进程树、时限、文件输入输出 | Rust 执行器与便携回退实现 |
| 持久化 | 任务、请求、步骤状态和本机资源容量 | SQLite 与各次尝试的文件 |

新增求解器优先增加接入包或程序，领域特有选择保留在相应实现内。保留求解器完整 API，也保留已有导入、调用、标识、环境绑定和研究记录。

## 已有能力

- 发现接口统一读取双语目录和独立安装的接入包。接入包可为已有求解器增加程序和按需指南，无须改动核心记录。读取元数据不导入科学软件；提交的扩展程序保留源码与来源。见[接入包](../skills/optical-computation/references/integrations.md)。
- 每个目录条目说明 Python、原生会话、可执行程序、自动化、服务或软件内部运行的路径。配方准备独立环境；COMSOL、Lumerical、OpticStudio、CST 提供会话适配，其他原生语言使用一致的输入输出约定。见[原生软件](NATIVE.md)。
- 参数扫描、有界优化、依赖工作流和 episode 采集以持久任务运行。同一主机上的多个进程共同分配资源。MCP 等待可以单独取消，并继续响应其他请求。见[执行](EXECUTION.md)。
- `CHECKPOINT` 保存显式程序状态与不可变产物引用；优化保存完成的评估，分组扫描保存完成的参数点。`resume_run` 保留成功步骤与先前输出。搜索与稳定分页帮助新会话找回工作。见[接续](../skills/optical-computation/references/continuation.md)。
- 带说明的数组保留单位、坐标、相位和符号约定、归一化与参考面。文件绑定避免通过 JSON 复制大数组；部分读取、绘图和 TypeScript 下载用于查看结果。已有 HCIPy→POPPY、RCWA 单元→超透镜传播、器件耦合→电路模型的组合。

## 从研究任务扩展

先确定观测量、物理假设以及后续研究者需要的结果，复用已有程序或发布包含程序的接入包。科学依赖留在求解器环境。输入注明单位，输出保留采样与约定。根据问题选取守恒关系、解析极限、离散精度变化或独立模型，解决真正影响结论的数值问题。

Agent 的初始回复保持简短，按请求展开程序输入、模型和源码；由任务选择相关指南。新增接口时同步 Python、CLI、MCP 与 TypeScript，复用已有格式。长程序在有科学意义的计算阶段完成、文件写好之后保存进度。远端计算先保存服务端任务编号，恢复时连接原任务。活的 SDK 对象保持在所属进程中，不假定可以序列化。

## 当前边界

目录范围宽于无人值守自动化范围。只能在软件内部运行的应用仍需自身流程；商业 SDK 需要匹配的安装、许可和凭据。缺少授权安装时，会话生命周期使用替代 SDK 运行。新增接入应写清具体路径和实际运行过的操作。

本机容量管理不会替代 GPU 设备选择、MPI 分配或集群队列；这些由启动程序或外部调度器完成。可复用远端任务适配需要保存任务编号、重新连接、取回结果并取消实际远端任务；提交回复丢失时不能产生重复计算。

已有数据转换与示例尚未覆盖每类光学对象和模型。后续科学能力应继续丰富可复用程序，以及网格、光线、版图、耦合器件和不确定度的结果表达。可选学习框架保留自身策略和训练算法。

## 融合与发布

从当前 main 开始，阅读相关开放贡献；每次提交完成一项可用行为，保留贡献者历史与研究记录。目录和宿主包从规范源文件生成，发布构建排除仅安装在维护者电脑上的接入包。

运行相关程序、运行时和客户端用例，再完成仓库工作流。说明行为变化、实际结果与仍需外部设备或软件的部分。发布时同步软件包、客户端、原生执行器和插件的版本；个人与 EnvFoundry 仓库保持相同的集成历史。
